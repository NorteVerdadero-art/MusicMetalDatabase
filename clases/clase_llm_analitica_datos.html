LLMs para Analítica de Datos

Ya sabes extraer, modelar y comunicar. Hoy sumas un LLM al proceso sin regalarle el criterio: qué compartirle, cómo pedirle y cómo comprobar lo que responde.

Contexto

Un LLM escribe un query o una gráfica en segundos. Lo que tarda es saber si el resultado está bien. La clase gira alrededor de ese punto: darle buen contexto, pedir con estructura y verificar siempre contra tu propia base.

Todos los ejemplos de hoy salen de MusicWorks. Los números de cada demo están verificados contra la base real.

Esta clase supone que ya viste la de Subconsultas y Agregaciones: los errores que vas a cazar (promedio de razones, JOIN que duplica, NOT IN con NULL) se explican ahí.

Cómo leer esto

Amarillo pégalo solo después de anonimizar, redondear o tapar nombres.
Rojo no se pega, ni resumido con nombres.

Ejercicio rápido: clasifica cada elemento. Al elegir, aparece la razón.

La regla de la muestra

Un LLM necesita el esquema (tablas y columnas) y entre 5 y 20 filas de ejemplo para entender tu base. La tabla completa sobra. Con esa muestra ya puede escribir el query; el query lo corres tú, contra los datos completos, en tu máquina.

Revisa tu herramienta

Antes de usar un LLM con datos de trabajo, revisa la configuración de privacidad de tu cuenta y lo que dice la política de tu plan sobre el uso de tus conversaciones. Cambia de una herramienta a otra y de un plan a otro.

Bloque 2 · El flujo de trabajo real

Lo que todos creen que pasa y lo que pasa de verdad

El flujo que todos imaginan

  1. Escribo mi pregunta.
  2. El LLM me da el query.
  3. Lo copio y lo presento.

Rápido, y con un riesgo alto: nadie comprobó nada.

El flujo que funciona

  1. Preparo el contexto.
  2. Pido un borrador.
  3. Lo verifico contra mi base.
  4. Devuelvo el error o el resultado y corrijo.
  5. Guardo el prompt y el query validados.

El tiempo se reparte distinto: menos escribir, más comprobar.

Recorre cada paso del flujo real. Cada uno trae un ejemplo de este mismo curso.

Dónde el LLM falla con más frecuencia

Sumas y promedios largos hechos de memoria. Columnas o tablas que nunca vio. Cifras sin fuente. Causalidad ("subió porque..."). En todos esos casos, calcula con SQL y usa el LLM para redactar y estructurar.

Bloque 3 · Qué y cómo pedir

Un prompt para datos tiene partes, y cada una evita un error distinto

Arma el prompt activando sus partes. A la derecha ves el texto que enviarías y qué tan completo está. Prueba las tres preguntas de negocio.


      

    

  

  

    Qué se rompe cuando falta cada parte
    
Sin esquema, inventa nombres de columna. Sin grano, mezcla niveles y duplica filas. Sin definición de la métrica, promedia razones en vez de dividir totales. Sin restricciones, devuelve SELECT * o sintaxis de otro motor. Sin verificación, no tienes cómo saber si el total cuadra.

  

  

    Dos hábitos que ayudan mucho
    
Pedirle que haga preguntas antes de responder cuando falte información. Y cambiar una sola cosa por mensaje al iterar, así sabes qué produjo cada mejora o cada error.

  






  Bloque 4 · Verificar
  
Que un query se ejecute sin error no garantiza que el resultado sea correcto

  
El LLM no ve tu base. Puede escribir algo que ejecuta sin error y da un número equivocado. Cuatro comprobaciones te cubren casi todo.

  

    

      
1 · Reconciliar totales

      
El total de tu resultado debe coincidir con el total de la tabla base.

      SELECT SUM(streams) FROM streaming_weekly;
-- 2,154,997,804  (el cubo de streaming suma lo mismo)
    

    

      
2 · Contar filas

      
Si esperas una fila por combinación, cuenta las combinaciones posibles.

      -- género × tipo × DSP
-- 15 × 2 × 7 = 210 filas esperadas
    

    

      
3 · Revisión puntual

      
Toma una fila del resultado y calcúlala aparte, con un query mínimo.

      SELECT SUM(sw.streams) FROM streaming_weekly sw
JOIN tracks t ON t.track_id=sw.track_id
JOIN releases r ON r.release_id=t.release_id
JOIN artists a ON a.artist_id=r.artist_id
JOIN genres g ON g.genre_id=a.genre_id
JOIN dsps d ON d.dsp_id=sw.dsp_id
WHERE g.genre_name='Doom Metal'
  AND a.artist_type='independent'
  AND d.dsp_name='Spotify';
-- 66,806,556
    

    

      
4 · Vigilar el grano

      
Un JOIN a una tabla con varias filas por llave multiplica tus totales. Es el error más silencioso.

      -- correcto
SELECT SUM(streams) FROM streaming_weekly;
-- con JOIN a playlist_placements
SELECT SUM(sw.streams) FROM streaming_weekly sw
JOIN playlist_placements pp ON pp.track_id=sw.track_id;
    

  


  
Lo que hace un JOIN duplicado, con números reales

  

  

  

    El promedio de razones
    
Promediar el cost_per_conversion de cada campaña da $2.92. Dividir el gasto total entre las conversiones totales da $2.68. Las campañas grandes deben pesar más que las chicas, y el promedio simple las trata igual. Cuando pidas una razón, define el numerador y el denominador en el prompt.

  


  

    🖥️ Cuando el query falla, el error también es información
    
Un query armado sin la tabla de DSPs devolvió esto al ejecutarse:

    Error Code: 1054. Unknown column 'd.dsp_name' in 'field list'
    
Pegar el error completo al LLM funciona mejor que describirlo. La corrección fue agregar JOIN dsps d ON d.dsp_id = sw.dsp_id, y el resultado se comprobó con las técnicas 1 y 2: 210 filas y el mismo total.

  Bloque 6 · Gráficas con un LLM
  
Cada pregunta pide un tipo de gráfica distinto

  
Un LLM puede devolver un archivo HTML con la gráfica lista, sin instalar nada. Lo que decide la calidad es lo que tú le pides: los datos reales, el tipo de gráfica y el mensaje. Elige un tipo de pregunta para ver el prompt, el error típico y el resultado esperado.

  

  


  

    Cómo pedir el archivo
    
Datos pega la tabla real de tu resultado. Describirla de memoria produce números inventados.

    
Formato un solo archivo .html con SVG, sin librerías externas, que abra con doble clic.

    
Mensaje dile la conclusión que debe mostrar el título.

    
Estilo un color de resalte, eje desde cero en barras, sin decoración.

  


  

    Lista de revisión antes de presentar
    
1) Cada número de la gráfica está en tu tabla. 2) No hay filas o categorías que tu tabla no tiene. 3) El eje de barras empieza en cero. 4) El orden ayuda a leer. 5) El título coincide con lo que muestran los datos.

  Bloque 7 · Conectar la base
  
Pegar datos o dejar que el LLM consulte tu base

  
Existen herramientas que le dan al LLM acceso directo a tu base para que ejecute sus propios queries. Así se construyeron estas clases: el LLM escribe el query, lo corre contra MusicWorks, ve el resultado y corrige. Es más rápido y exige más cuidado.

  

    
Pegar esquema y muestraLLM conectado a la base

    
      
VelocidadCada ciclo lo corres tú.El LLM ejecuta, ve el error y corrige solo.

      
Exposición de datosSolo lo que pegas.Todo lo que el usuario de la base pueda leer.

      
Riesgo de una acción erróneaNinguno: tú ejecutas.Depende de los permisos que le des.

      
VerificaciónManual, en tu cliente.Sigue siendo necesaria: ejecutar un query no lo valida.

    
  

  

    Condiciones mínimas
    
Un usuario de solo lectura, limitado a la base de práctica. Ninguna contraseña dentro del prompt ni en archivos compartidos. Revisar cada query antes de aprobar su ejecución y pedir LIMIT mientras exploras.

  

  

    🖥️ Un usuario de solo lectura en MySQL
    CREATE USER 'analista_ro'@'localhost' IDENTIFIED BY 'cambia-esta-clave';
GRANT SELECT ON musicworks.* TO 'analista_ro'@'localhost';
    
Con este usuario, la herramienta puede consultar y no puede modificar ni borrar nada.

1 · PrivacidadCompartes esquema y muestra, anonimizas lo amarillo y dejas fuera lo rojo.

3 · BorradorPides con formato, restricciones y una consulta de reconciliación.

    Lo que te llevas
    
El LLM acelera la escritura. La responsabilidad del número sigue siendo tuya, y por eso el paso que más tiempo merece es comprobarlo.
