Sheets y SQL: el mismo trabajo, distintas escalas
15 min · Por qué no son herramientas alternativas sino complementarias

Google Sheets y SQL resuelven el mismo problema — organizar y consultar datos — pero en contextos distintos. Sheets es visual, inmediato y perfecto para datasets pequeños. SQL es textual, preciso y necesario cuando los datos viven en una base de datos o tienen millones de filas.

En la industria musical, el flujo real es: los datos de streaming, revenue y catálogo viven en bases de datos de distribuidoras y plataformas. SQL extrae lo que necesitas. Sheets recibe ese resultado y lo convierte en el reporte que presentas al artista, manager o sello.

La habilidad clave no es SQL o Sheets — es saber cuándo usar cuál y cómo conectarlos. Eso es lo que construimos hoy con datos reales del catálogo Alzada.

Google Sheets — cuándo
  • Menos de 100,000 filas
  • Exploración visual rápida
  • Reportes para stakeholders
  • Gráficas y tablas dinámicas
SQL — cuándo
  • Más de 100,000 filas
  • Datos en bases de datos
  • Consultas repetibles exactas
  • Cuando Sheets se congela

02 · GROUP BY y Agregaciones
SQL hace la tabla dinámica en la base de datos
20 min · Lo que en Sheets es tabla dinámica, en SQL es GROUP BY
Pregunta de negocio

¿Cuántos tracks tiene cada sello del catálogo Alzada?

En Sheets harías una tabla dinámica: filas = PyC, valores = COUNT. En SQL escribes GROUP BY PyC con COUNT(*). Resultado: Rise Records 15, Blegh! Label 13, Alzada Corp. 13.

Estructura GROUP BY
Funciones de agregación
COUNT(*) Cuenta filas — cuántos tracks por sello
COUNT(UPC) Cuenta solo valores no nulos — ignora vacíos
SUM() Suma total — revenue, streams, costos
AVG() Promedio — save rate promedio por plataforma
MAX() / MIN() Extremos — fecha más reciente / más antigua
Regla de GROUP BY

Toda columna en el SELECT que no sea una función de agregación debe estar en el GROUP BY. Si seleccionas PyC y Estatus_Distribucion, ambas deben ir en GROUP BY PyC, Estatus_Distribucion. Es el error #1 al principio.

03 · ORDER BY, LIMIT y HAVING
Rankings y filtros avanzados sobre el catálogo
20 min · Las tres cláusulas que convierten una query en un reporte listo para Sheets

ORDER BY

Ordena el resultado antes de enviarlo a Sheets. DESC de mayor a menor. ASC de menor a mayor.

🎵 Tracks más recientes del catálogo Alzada primero

LIMIT

Devuelve solo los primeros N resultados. Siempre va después de ORDER BY para que sea un ranking real.

🎵 Top 5 artistas con más tracks en el catálogo

HAVING

Filtra después de agrupar. WHERE filtra filas. HAVING filtra los grupos ya calculados.

🎵 Solo sellos con 8+ tracks distribuidos

WHERE vs HAVING — la confusión más común

WHERE actúa antes de agrupar — filtra filas individuales. HAVING actúa después de agrupar — filtra grupos. Si tu condición usa COUNT(), SUM(), AVG() u otra función, siempre es HAVING. Si filtra un valor de fila individual, siempre es WHERE.

04 · Connected Sheets
Correr SQL directamente desde Google Sheets
20 min · La integración nativa de Google — sin copiar, sin pegar
La integración más poderosa

Connected Sheets te permite escribir SQL en Google Sheets y ver el resultado como tabla — sin salir de Sheets.

Funciona con BigQuery (base de datos de Google Cloud). Cuando tu sello o distribuidora tiene datos en BigQuery, los consultas directamente desde tu spreadsheet sin exportar nada.

¿Qué es Connected Sheets?

Una función nativa de Google Sheets (Workspace) que conecta tu hoja con BigQuery. Escribes SQL en un panel lateral y el resultado aparece como tabla en tu hoja.

No exportas CSV. No copias resultados. La tabla se actualiza con un clic cuando los datos cambian.

¿Cuándo lo necesitas?

Cuando el sello o empresa tiene datos en Google BigQuery o Cloud SQL. Si tienes Google Workspace Business o Enterprise, probablemente ya tienes acceso.

Para datos de Spotify o distribuidoras que llegan como CSV — importas directamente a Sheets. El flujo SQL aplica cuando hay una BD propia.

Cómo activar y usar Connected Sheets
1
Abrir la conexión

En Google Sheets ve a Datos → Conectores de datos → BigQuery. Se abre un panel lateral para seleccionar tu proyecto y dataset.

Datos → Conectores de datos → BigQuery
2
Seleccionar la fuente

Elige el proyecto de BigQuery, el dataset y la tabla. O elige "Consulta personalizada" para escribir tu propio SQL.

Consulta personalizada → escribes tu SQL aquí
3
Escribir la query

Escribes tu SQL en el panel lateral. Exactamente las mismas cláusulas que aprendiste: SELECT, WHERE, GROUP BY, ORDER BY, LIMIT.

SELECT PyC, COUNT(*) FROM metadata_master GROUP BY PyC
4
Ver el resultado en la hoja

El resultado aparece como tabla en tu Sheets. Puedes crear tablas dinámicas y gráficas sobre esa tabla — todo conectado en tiempo real.

Clic en "Insertar resultados" → tabla en hoja activa
5
Actualizar cuando cambien los datos

Cuando llegan nuevos datos a BigQuery, haces clic en "Actualizar" en el panel. La tabla se recalcula sin reescribir nada.

Panel lateral → Actualizar datos → la tabla se recarga
El flujo que usarás el 90% del tiempo

En la práctica diaria, los reportes de streaming llegan como CSV de distribuidoras. El flujo será: recibes CSV → lo limpias con lo de Clase 3 → lo analizas en Sheets. SQL entra cuando trabajas con bases de datos propias o cuando el volumen hace que Sheets no aguante.
